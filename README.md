# solution-writer

整体解决方案撰写专家 - 将需求文档转化为结构化投标解决方案文档。

## 功能特性

- **需求解析** - 读取并解析甲方业务需求文档，建立"需求→方案"映射
- **方案撰写** - 使用售前投标语言，严格遵循评分细则章节结构
- **文档生成** - 生成带格式的 Word 文档（.docx）
- **架构图生成** - 使用 PIL 生成系统架构图 PNG

## 快速开始

```bash
# 在 Claude Code 中使用
/solution-writer 请根据以下文档生成整体解决方案
```

## 执行流程

```
1. 输入确认 → 2. 需求解析 → 3. 结构解析 → 4. 方案撰写 → 5. 架构图生成 → 6. 文档合并 → 7. 质量校验
```

## 输出规范

### 文档结构示例

```
3.2.1 总体技术方案
  └── 总体架构、业务架构、数据架构、安全架构 + 架构图

3.2.2 协同审批模块
  └── 数据库建设、表单流程管理、审批规则...
```

### 字体字号规范

| 元素 | 字体 | 字号 | 加粗 | 行距 |
|------|------|------|------|------|
| 正文 | 仿宋 | 12 号 | 否 | 固定 20 磅 |
| 二级标题 | 仿宋 | 15 号 | 是 | - |
| 三级标题 | 仿宋 | 14 号 | 是 | - |

## 核心能力

1. **需求解析能力** - 确保 100% 覆盖原始需求
2. **方案撰写能力** - 售前投标语言，正式严谨
3. **文档生成能力** - 带格式的 Word 文档
4. **架构图生成能力** - 多层架构体系可视化

## 内容撰写规范

每个模块必须包含：
1. 功能说明（做什么）
2. 实现方式（怎么做）
3. 应用价值（解决什么问题）

## 使用示例

```
/solution-writer 请根据以下文档生成整体解决方案：
- 原始需求：C:/项目/原始需求.md
- 文档结构：C:/项目/文档撰写需求.md
- 输出名称：某某系统解决方案.docx
```
